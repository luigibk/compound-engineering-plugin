# Go Tooling: Build Tags, go:generate, ldflags, Cross-Compilation

Target: Go 1.21+

---

## Build Tags

Build tags (also called build constraints) conditionally include or exclude files from a build. Since Go 1.17, use the `//go:build` comment syntax (replaces the old `// +build` syntax).

### Syntax

Place the build constraint on the first line of the file, before the `package` declaration, followed by a blank line:

```go
//go:build linux && amd64

package platform
```

Multiple conditions:

```go
//go:build (linux || darwin) && !cgo
```

### Common Use Cases

**Operating system and architecture:**

```go
//go:build linux

package signal

import "syscall"

func platformSignals() []os.Signal {
    return []os.Signal{syscall.SIGTERM, syscall.SIGINT}
}
```

**Excluding files from normal builds (integration tests, slow tests):**

```go
//go:build integration

package db_test

// Only compiled and run when: go test -tags integration ./...
```

**Feature flags:**

```go
//go:build pprof

package server

import _ "net/http/pprof"  // register pprof handlers only in pprof builds
```

### Negation

```go
//go:build !windows  // compile on everything except Windows
```

### Running Builds with Tags

```bash
go build -tags linux,amd64 ./...
go test -tags integration ./...
go test -tags "integration postgres" ./...
```

## go:generate

`go:generate` runs arbitrary commands as part of the source generation workflow. It is not run by `go build` — you invoke it explicitly.

### Directive Format

```go
//go:generate command arguments

// Examples:
//go:generate stringer -type=Direction
//go:generate mockgen -source=store.go -destination=mock_store.go -package=mocks
//go:generate protoc --go_out=. user.proto
```

Place directives in the `.go` file closest to what they generate. For a type, place the directive in the file that defines the type.

### Running

```bash
go generate ./...              # run all directives in the module
go generate ./internal/user/   # run directives in one package
```

### Checking Generated Files Into Version Control

Generated files should be committed so that callers do not need the generator tools installed. Add a comment at the top of generated files:

```go
// Code generated by stringer -type=Direction; DO NOT EDIT.
```

The Go tools recognize the `DO NOT EDIT` comment and exclude these files from certain checks.

### Common Generators

| Generator | Purpose |
|-----------|---------|
| `stringer` | `String()` method for `iota` enums |
| `mockgen` (gomock) | Interface mocks for testing |
| `protoc` | Protocol Buffers → Go types |
| `sqlc` | SQL queries → type-safe Go functions |
| `wire` | Compile-time dependency injection |
| `enumer` | Enum helpers (JSON, SQL, parsing) |

## ldflags: Injecting Version Information

Use `-ldflags` to inject build-time values (version, commit hash, build date) into variables at link time without modifying source files:

### Source Setup

```go
// package version
package version

// These variables are set by the linker via -ldflags at build time.
var (
    Version   = "dev"
    Commit    = "none"
    BuildDate = "unknown"
)
```

### Build Command

```bash
go build \
  -ldflags "-X myapp/internal/version.Version=1.2.3 \
            -X myapp/internal/version.Commit=$(git rev-parse --short HEAD) \
            -X myapp/internal/version.BuildDate=$(date -u +%Y-%m-%dT%H:%M:%SZ)" \
  ./cmd/server
```

### Makefile Target

```makefile
VERSION := $(shell git describe --tags --always --dirty)
COMMIT  := $(shell git rev-parse --short HEAD)
DATE    := $(shell date -u +%Y-%m-%dT%H:%M:%SZ)

LDFLAGS := -ldflags "\
  -X myapp/internal/version.Version=$(VERSION) \
  -X myapp/internal/version.Commit=$(COMMIT) \
  -X myapp/internal/version.BuildDate=$(DATE)"

build:
    go build $(LDFLAGS) ./cmd/server
```

### Additional ldflags

```bash
# Reduce binary size: strip debug info and symbol table
-ldflags "-s -w"

# Combined with version injection:
-ldflags "-s -w -X main.version=1.0.0"
```

## Cross-Compilation

Go cross-compiles natively. Set `GOOS` and `GOARCH` environment variables:

### Common Targets

```bash
# Linux amd64 (most common server target)
GOOS=linux GOARCH=amd64 go build ./cmd/server

# macOS ARM (Apple Silicon)
GOOS=darwin GOARCH=arm64 go build ./cmd/server

# Windows amd64
GOOS=windows GOARCH=amd64 go build -o server.exe ./cmd/server

# Linux ARM64 (Raspberry Pi, AWS Graviton)
GOOS=linux GOARCH=arm64 go build ./cmd/server
```

### All GOOS/GOARCH Pairs

```bash
go tool dist list  # prints all supported OS/arch combinations
```

### CGo and Cross-Compilation

CGo does not cross-compile easily. If your module uses CGo (check with `go build -v ./...` for `CGO_ENABLED=1`), either:
- Disable CGo: `CGO_ENABLED=0 GOOS=linux go build ./...`
- Use a Docker cross-compilation container

Pure Go modules (no CGo) cross-compile transparently.

### Makefile Multi-Platform Release

```makefile
PLATFORMS := linux/amd64 linux/arm64 darwin/amd64 darwin/arm64 windows/amd64

release:
    @for platform in $(PLATFORMS); do \
        GOOS=$$(echo $$platform | cut -d/ -f1); \
        GOARCH=$$(echo $$platform | cut -d/ -f2); \
        output="dist/server-$$GOOS-$$GOARCH"; \
        [ "$$GOOS" = "windows" ] && output="$$output.exe"; \
        CGO_ENABLED=0 GOOS=$$GOOS GOARCH=$$GOARCH go build $(LDFLAGS) -o $$output ./cmd/server; \
        echo "Built $$output"; \
    done
```

## Useful go tool Commands

```bash
# Check escape analysis — which variables escape to the heap
go build -gcflags='-m' ./...

# Verbose escape analysis
go build -gcflags='-m -m' ./...

# Check if any package does not compile
go build ./...

# Vet: catch common mistakes (unused variables, unreachable code, etc.)
go vet ./...

# Print the dependency graph
go mod graph

# Find why a dependency is required
go mod why golang.org/x/sync

# Remove unused dependencies and add missing ones
go mod tidy

# List all direct and indirect modules
go list -m all

# Run all tests with race detector
go test -race ./...

# Run benchmarks
go test -bench=. -benchmem ./...
```

## go.env and GOFLAGS

Set persistent build flags with `GOFLAGS` or `go env -w`:

```bash
# Permanently disable CGo for this environment
go env -w CGO_ENABLED=0

# Always build with race detector (useful in CI)
export GOFLAGS="-race"

# View all Go environment variables
go env
```

The `GOENV` file (default `~/.config/go/env`) stores persistent settings set via `go env -w`.
